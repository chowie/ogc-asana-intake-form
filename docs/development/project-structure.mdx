## Conventions worth knowing

**Shared helpers are prefixed `_`.** `netlify/functions/_shared/` is skipped by
Netlify's function discovery, so those files are importable modules, not
deployed endpoints.

**Client never holds secrets.** Anything sensitive goes through a function.
`src/lib/asana.js` posts to the function, not to Asana.

**The roster is the allowlist.** `data/roster.json` drives both the UI dropdown
(`src/config/staff.js`) and server-side GID validation
(`netlify/functions/_shared/roster.js`). One file, two consumers.

**Refs guard async re-entrancy.** `App.jsx` uses `useRef` flags
(`philipInFlight`, `confirmInFlight`) rather than state, because state updates
aren't visible within the same tick — that's what prevents duplicate tasks on a
double-click.

## Build

`netlify.toml`:

```toml
[build]
  command = "node scripts/fetch-roster.mjs && npm run build"
  publish = "dist"

[functions]
  directory = "netlify/functions"
  node_bundler = "esbuild"

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

The roster fetch runs *before* Vite so the live roster is baked into the bundle.
