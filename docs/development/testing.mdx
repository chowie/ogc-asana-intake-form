## Patterns used

**Mocking the roster.** `src/config/staff.js` is replaced with `vi.mock` +
`vi.hoisted` in `IntakeForm.test.jsx`, so the tests don't depend on whatever
happens to be in `data/roster.json`.

```js
const { STAFF } = vi.hoisted(() => ({ STAFF: [/* fixtures */] }))
vi.mock('../config/staff.js', () => ({ STAFF, findStaff: (n) => ... }))
```

**Mocking fetch.** `vi.stubGlobal('fetch', ...)` — used in
`PassphraseGate.test.jsx` and the function tests.

**The PII guard.** `data/__tests__/roster-placeholder.test.js` fails the build if
`data/roster.json` looks like real staff data rather than the placeholder. This
exists because real names, emails, and Asana GIDs were committed once already.

<Warning>
  Don't "fix" that test by loosening it after running `npm run refresh-roster`
  locally — the generated roster is not meant to be committed. Revert
  `data/roster.json` before committing.
</Warning>

## What isn't covered

No end-to-end tests. The Asana and Anthropic APIs are mocked at the `fetch`
boundary in every test — nothing in CI hits a live API.
