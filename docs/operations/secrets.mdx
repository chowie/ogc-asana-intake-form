Six secrets, all server-side. None is bundled into client JS — no variable here
carries a `VITE_` prefix, which is what would expose it.

## Blast radius

| Secret | If leaked |
|---|---|
| `PASSPHRASE` | Anyone can open the form and create Deacon tasks |
| `AUTH_SECRET` | Attacker can forge session tokens and call every protected function directly |
| `ASANA_PAT` | Full access to the workspace as the token owner |
| `ANTHROPIC_API_KEY` | Anthropic billing runs on someone else's requests |
| `NOTION_TOKEN` | Read access to the roster database (names, emails, GIDs) |
| `UPSTASH_*` | Read/write on the rate-limit Redis — low value on its own |

## Rotating `AUTH_SECRET`

```bash
npm run gen-secret   # prints a 32-byte base64url value
```

Set it in Netlify **and** in local `.env`. Takes effect on the next function
invocation.

<Warning>
  Rotation invalidates every live session immediately. Anyone mid-request gets a
  403 and has to re-enter the passphrase. Their form content is lost. Rotate
  outside of Sunday mornings and event weeks.
</Warning>

## Rotating `PASSPHRASE`

Set the new value in Netlify, then tell staff. There's no grace period — the old
passphrase stops working on the next invocation, though **existing sessions
survive** because they carry a signed token rather than the passphrase itself.

<Tip>
  Sequence it as: change the value → sessions keep working for up to an hour →
  announce the new one. That's the least disruptive order.
</Tip>

## Rotating `ASANA_PAT`

<Steps>
  <Step title="Create a new PAT">
    Asana → profile → **My Settings → Apps → Personal access tokens**.
  </Step>
  <Step title="Update Netlify">
    Set `ASANA_PAT` to the new value.
  </Step>
  <Step title="Test a submission end to end">
    Both `create-task` and `attach-task` use it, and `attach-task` also needs the
    preflight `GET` to succeed.
  </Step>
  <Step title="Revoke the old token">
    Only after the test passes.
  </Step>
</Steps>

<Note>
  A PAT belongs to a *person*, not the church. If that person leaves, task
  creation breaks. Consider whether it should be issued from an account the
  office controls.
</Note>

## Rotating `ANTHROPIC_API_KEY`

Create a new key in the Anthropic Console, update Netlify, verify Philip
responds, then delete the old key. No rebuild needed.

## Rotating `NOTION_TOKEN`

Update it in Netlify, then **trigger a rebuild** — unlike the others, this one is
read at build time, so a deploy is required for it to be exercised at all. Watch
the build log for `[fetch-roster] Wrote N entries`.

## Hygiene

- `.env` is gitignored. Keep it that way.
- `.env.example` holds placeholders only — never paste a real value in.
- Rotate `ASANA_PAT` and `PASSPHRASE` when someone with access leaves.
- Netlify build logs are visible to anyone with site access; the functions log
  warnings but never log secret values.
